# Variants: rows that grow, blocks that appear, stripes

Implementation notes for the second expressiveness milestone (M8) of the paramdoc experiment on `feat/paramdoc`,
written the same day as the wrapping-slot notes (`2026-10-25-wrapping-slots.md`), which this builds on. Same
experiment: a browser runtime fills a document Typst laid out once, so the 24 MB compiler is not shipped, and
every runtime PDF must equal Typst's own layout of the same data.

## The problem

Three things real templates do were impossible, for one underlying reason. A table row was one fixed height,
so a wrapping slot in a row could not make the row taller. A block could not be present for one document and
absent for another. Rows could not alternate their fill. The reason: the runtime may only do trivial geometry or
pick among things Typst already produced, and Typst had produced exactly one layout per band.

The repository's own templates asked for two of the three (the demo report's alternating fill, the outcomes
template's sections of varying height); conditionals were not in any template, but the same machinery gives
them away for nothing. The question was whether a band could have *several* Typst layouts without giving up
the isolation guarantee (nothing outside the slots moves with the data) or the exactness guarantee.

## What was built

One mechanism: a band may declare `variants: n` and a selector, and then exists as n fragments in the exported
document. The exporter lays each variant out by compiling the fixture again with `sys.inputs.paramdoc-variant`
set to `"<band>=<k>"`, which forces every instance of that band to variant k; the band's fragment from that
compile becomes variant k. The runtime picks one fragment per instance by the selector and places it; page
breaking already measured per instance, so rows of different heights paginate unchanged.

- **Dialect** (`fixtures/*/paramdoc.typ`): `repeat(name, rows, make, variants: n, select: ...)` calls
  `make(row, v)` with the instance's variant; `choice(name, natural, make, select: ...)` is a single block in
  several variants; `variant(name, natural)` returns what the data says in the sample compile and the forced
  value in a variant compile; `slot(..., lines: auto)` inside such a band takes as many lines as its text needs
  in the sample compile (measured in Typst, capped by the band's variant count) and the forced count otherwise.
  Selectors: `("parity",)`, `("flag", key)`, `("lines", slot)`.
- **IR v6** (`ir/`): `Band.fragments` (one per variant) and `Band.select`; a `choice` block kind; slots carry
  `auto_lines`.
- **Exporter** (`export/`): reads the band metadata; relaxes the fixed-row-size rule for bands with variants;
  runs the forced compiles after the sample compile (`build`), checks that each forced document equals the sample
  everywhere outside the bands, adopts the forced compile's fonts into the sample's font table (numbering is by
  first use and differs between compiles), checks that every sample instance is one of the variants (by its
  declared variant, or by height for `lines`), and that a `lines` band's variants grow strictly with the line
  count. The fuzz and every reference compile go through the same path, so the layout of every variant is
  checked not to depend on the data.
- **Runtimes** (`runtime/src/lib.rs`, `ts/runtime.ts`): `pick` by parity, by a `true` in the data, or by the line
  count the text needs, computed exactly as the dialect computes it in Typst (from the stacked height of the
  broken lines, so a whitespace-only line counts for nothing); `choice` blocks placed with the document's data.
- **Fixtures**: the report's rows alternate their fill again (two variants by parity); the transcript's rows are
  one to three lines tall by their title (`lines: auto`, three variants) and end with an "Awarded with honours"
  block that exists only when the data says so (`choice`, by flag), with a second data case where it does not;
  the long transcript paginates 42 rows of mixed heights. The demo page's document is re-exported with stripes.
- **Proof** (`check.sh`, rewritten): every fixture gets a Typst reference for each of its data cases, both
  runtimes are checked against each by glyph positions and pixels, and the honours block's presence is checked
  on both data files.

## What had to be learned

- The sample compile must render each instance in the variant the data calls for, so that Typst's layout of the
  sample is what the runtime produces for the sample data. Otherwise there is no oracle: a sample with all rows in
  variant 1 cannot check a runtime that stripes them. Hence `variant(name, natural)`.
- A `lines: auto` slot cannot know which band it is in, and a closure cannot see the row index, so the band
  publishes itself through a Typst `state` and the dialect's `repeat` hands the variant to `make`. Reading the
  width to measure against needs `layout`, which makes the slot block-level; that is fine in a table cell.
- A closure parameter named `v` shadows Typst's `v()` spacing function. Name it something else.
- Typst's font numbering in the exporter is by first use; a variant that introduces a font (a bold line) changes
  the numbers, so fragments from another compile must be re-pointed at the sample's font table.

## Verification

Both runtimes against Typst's layout of the same data, glyph ids and positions within 1e-3 pt, then pixels at
150 dpi, then the Rust trace against the TypeScript trace:

| Check | Result |
|---|---|
| report with striped rows | glyph-identical; 1 pixel differs (the report's known one) |
| transcript with one-, two- and three-line rows and the honours block | glyph-identical, pixel-identical |
| transcript without honours, different titles | glyph-identical, pixel-identical |
| long transcript, 42 rows of mixed heights, honours off | 2 pages, Rust and TypeScript traces identical, no honours line |
| fuzz, every fixture, each variant laid out per sample | 0 leaks |
| veraPDF PDF/UA-1 on the new PDFs | PASS |
| `check.sh` | 80 passed, 0 failed, 1 skipped (the demo step without a server) |
| demo page, paramdoc engine, 200 striped reports on 4 workers | all rendered |

## Covered now, with examples

- The report's course table alternates its row fill exactly as the compiler's version does.
- A transcript row grows to two or three lines when its title needs them, and the rows after it move down; a
  forty-two-row transcript with nine long titles paginates onto two pages with the header repeated.
- "Awarded with honours." appears below the totals for a student with `honours: true` and leaves no gap for one
  without.
- A title that needs more lines than the band has variants gets the slot's overflow policy on the last variant,
  here an ellipsis.

## Open

- **One selector per band.** Stripes *and* variable height on the same rows would need the product of the
  variants (2 × 3 layouts) and a combined selector. Not built; no fixture needed it.
- **Variants of a repeat region as a whole** (a different header for continuation pages, say) and **nested
  repeats** (sections of rows) are untouched; the flow model is still a sequence of static blocks, repeat
  regions and choice blocks.
- **An `index` selector** (the data names the variant directly) would be a few lines in each runtime and the
  dialect; left out until a template wants it.
- **Forced compiles make the sample page taller** when every row takes its tallest variant; a fixture whose
  sample then spills onto a second page fails the export with the existing one-page rule. Use fewer sample rows.
- **Line counting at a tie.** The dialect measures a `lines: auto` slot by height and rounds; the runtimes copy
  that arithmetic. A text whose first line is nothing but whitespace lands near a rounding tie, and float noise
  could make Typst and the runtime pick different variants. Not seen in the fuzz; recorded in the handover.
- **Justified text** remains the largest gap for the slots themselves; the wrapping-slot notes and the handover
  carry the conclusion from today's look at the pretext library (greedy only, no help there) and the shape of a
  real port.

## How to run it

```sh
cd experiments/paramdoc && ./check.sh             # the whole proof; FUZZ=20 ./check.sh is quicker
cargo run -p paramdoc-export -- fixtures/transcript --fuzz 20 --reference fixtures/transcript/data.json --reference fixtures/transcript/data-nohonours.json
cargo run -p paramdoc-runtime -- ../../.build/paramdoc/transcript --data fixtures/transcript/data-long.json --out /tmp/long.pdf
```
